# 从零搭建自己的本地知识库

这份指南的思路来自一套“本地 Markdown + AI 协作”的个人知识库实践。原始分享见[飞书文档](https://my.feishu.cn/docx/FoLbdZXZzoX7TmxIiRycM5UhnJJ)。这里没有照搬原文，而是整理成能与本项目直接衔接的版本。

## 先说结论

Obsidian 不是替你思考的知识引擎。它更像一个稳定、可迁移的本地工作台：

- Markdown 文件归你自己；
- 双向链接和搜索让页面容易找到；
- Codex、Claude Code 等工具都能读取同一套文件；
- 换工具时不必搬走整套知识。

真正决定知识库质量的，是文件职责是否清楚、入口是否稳定、AI 是否按需读取、资料有没有可追溯的处理流程。

## 第一步：准备本地目录

在电脑上选一个长期不变的位置，例如：

```text
~/Documents/个人知识库
```

用 Obsidian 将它打开为一个 Vault。以后需要同步时，可以再选择 iCloud、Git 或其他方式；第一次搭建先把本地流程跑通。

## 第二步：建立三层结构

### 素材层

保存原文、文章、会议纪要、对话总结和课程资料。原始资料不直接覆盖。

### 笔记层

保存已经确认的个人信息、目标、项目、主题知识、课程内容和复盘。

### 规则层

保存 AI 的工作边界和接力方式：

- `AGENTS.md`：AI 接手时必须遵守的稳定规则；
- `README.md`：人和 AI 的共同入口；
- `index.md`：按内容定位页面；
- `log.md`：按时间记录更新；
- Skill：可复用、步骤较多的工作流。

`AGENTS.md` 不应该变成第二个知识库。细节流程放到 Skill，长期知识放到主题页面。

## 第三步：让脚本搭好骨架

安装本项目后运行：

```bash
python3 skills/local-materials-to-course-kb/scripts/init_personal_kb.py \
  --vault-root "~/Documents/个人知识库"
```

脚本只补缺失项，不覆盖已有内容。它会建立资料队列、课程知识库、复盘目录和基础入口文件。

## 第四步：让 AI 逐步认识你

不要一次让 AI 生成一份“完整人生档案”。更稳的方式是一次只问一个问题：

1. 你现在最重要的目标是什么？
2. 哪些项目正在进行？
3. 哪些判断已经确认，哪些只是推测？
4. 当前最需要沉淀的主题是什么？

每次回答后，让 AI：

- 更新最相关的页面；
- 标明已确认、历史记录、推断待确认或冲突待确认；
- 补上双向链接；
- 更新 `index.md`；
- 在 `log.md` 追加记录。

AI 不知道的内容就留空，不要让它把猜测写成个人事实。

## 第五步：从资料队列开始使用

把待处理文件放进：

```text
素材/待整理/TBD
```

然后使用本 Skill 盘点并处理。每次只做一个合理批次。完成后，原始资料进入 `Done`；需要人工判断的中间产物进入相应的 `待复核` 目录。

## 第六步：让知识按主题生长

不要把所有结论持续追加到一个“大总文档”。

推荐结构：

```text
01_知识主文档.md      # 主题导航和简短说明
01_知识主题/
├── 广告预算调整原则.md
├── 新品推广阶段判断.md
└── 复盘会议检查清单.md
```

每次任务只打开入口和相关主题页。这样即使积累数千份资料，单次上下文仍然由当前任务决定，而不是由整个知识库大小决定。

## 第七步：再考虑自动化

先手动跑通一两次，再配置自动化。本项目内置三套模板：

1. 资料沉淀队列；
2. 本地知识库每周体检；
3. 每周创作复盘。

默认都保持暂停。确认路径和边界无误后，再由你手动启用。

## 你真正要维护的四件事

- 入口是否还清楚；
- 新资料是否按批次收口；
- 主题页是否重复或过长；
- 待复核是否长期积压。

这四件事比追求复杂插件更重要。先把小而稳定的循环跑起来，知识库才会真的长成自己的工作系统。
