# 从零搭建自己的 Obsidian 个人知识库

> 本文转载并改编自[飞书原文](https://my.feishu.cn/docx/FoLbdZXZzoX7TmxIiRycM5UhnJJ)中的个人知识库方法，并参考 Andrej Karpathy 关于本地 raw/wiki 工作流的[公开 gist](https://gist.github.com/karpathy)。提示词、目录和执行步骤已针对本项目重新整理。

无需离开本页。按下面的顺序操作，就可以完成一套由 Obsidian 保存、Codex 协助维护、换对话也能接手的本地知识库。

## 完成后你会得到什么

```text
<你的 Vault>/
├── README.md                  # 人和 AI 的共同入口
├── AGENTS.md                  # AI 长期维护规则
├── index.md                   # 按内容定位页面
├── log.md                     # 按时间追加更新记录
├── 生活.md
├── 工作.md
├── 学习.md
├── 目标_核心目标.md
├── 项目/
├── 知识库/
├── 素材/
│   └── 待整理/
│       ├── TBD/
│       ├── Done/
│       └── 待复核/
├── reviews/
└── wiki/
```

Obsidian 负责本地文件、链接、搜索和人工阅读；Codex 负责采访、整理、更新和检查。Markdown 文件始终保存在你选择的目录里，不被某个 AI 工具锁住。

## 第一步：安装 Obsidian 和 Codex

1. **下载 Obsidian**：从[Obsidian 官方下载页](https://obsidian.md/download)下载并安装。
2. 按[Codex 官方文档](https://developers.openai.com/codex)安装或打开适合自己的 Codex 使用方式。
3. 暂时不要安装一堆 Obsidian 插件。先把目录、入口、采访和更新循环跑通。

## 第二步：选择 Vault 存放位置

选一个长期稳定、自己知道在哪里、方便备份的本地目录，例如：

```text
macOS:   ~/Documents/个人知识库
Windows: D:\Obsidian\个人知识库
```

第一次先用本地目录。iCloud、Git 或其他跨设备同步可以等结构稳定后再配置。

## 第三步：准备一份可追溯的个人摘要

这一步可选，但很有用。你可以让最常用的 AI 根据历史对话整理一份个人摘要，内容包括：

- 当前工作和长期方向；
- 正在进行的项目；
- 学习主题和兴趣；
- 已明确的偏好；
- 仍不确定或互相冲突的信息；
- 当前最想解决的问题。

摘要只是原始素材，不直接等于事实。保存后交给 Codex，让它继续采访和确认；不要让 AI 把推测写成你的真实信息。

## 第四步：把建库任务交给 Codex

在你准备使用的 Vault 目录中打开 Codex，复制下面这段提示词：

```text
请把当前目录作为我的 Obsidian 个人知识库，并担任个人知识库架构师。

开始创建文件前，先确认两个问题：
1. 知识库最终存放路径是什么？
2. 我现阶段最想解决的问题或建立的系统是什么？

确认后，请完成以下工作：

1. 建立素材层、笔记层、规则层三层结构。
2. 创建 README.md、AGENTS.md、index.md、log.md、生活.md、工作.md、
   学习.md、一个核心目标页，以及项目、知识库、素材、reviews、wiki 目录。
3. 素材层保存原文，不覆盖或润色原始资料。
4. 笔记中的信息区分：已确认、历史记录、推断待确认、冲突待确认。
5. 不编造我没有提供的信息；遇到冲突时同时保留并向我确认。
6. index.md 按内容记录主要页面入口，log.md 只追加带日期的更新记录。
7. AGENTS.md 只放稳定维护规则，不把它写成第二个知识库。
8. 建好骨架后，一次只问一个问题。每次回答后立即更新相关页面、
   双向链接、index.md 和 log.md，再问下一个问题。
9. 不扫描与当前问题无关的整个知识库。
10. 不记录 API Key、Token、密码、私钥、支付信息或证件信息。

先只复述你理解的路径、核心目标和预计创建的结构；确认无冲突后再写文件。
```

这段提示词刻意要求“先确认两个问题”。路径决定文件写到哪里，核心目标决定知识库先长哪一部分；这两件事不明确，越自动化越容易跑偏。

## 第五步：检查三层结构

### 素材层

保存原文、文章、会议纪要、对话摘要和课程资料。原始资料只读，不直接覆盖：

```text
素材/
└── 待整理/
    ├── TBD/       # 新资料入口
    ├── Done/      # 已完成资料，只读归档
    └── 待复核/    # 需要人工判断的草稿或复盘资料
```

### 笔记层

保存经过确认和整理的内容：

- `生活.md`：生活信息、设备、兴趣和待确认事项；
- `工作.md`：职业背景、业务领域和工作方法；
- `学习.md`：当前学习主题与学习偏好；
- `目标_*.md`：一个页面对应一个稳定目标；
- `项目/`：项目状态、下一步和阻塞项；
- `知识库/`：专题知识和课程知识。

### 规则层

- `README.md`：告诉人和 AI 这个知识库是什么、从哪里开始；
- `AGENTS.md`：告诉不同 AI 怎样读取、写入、验证和交接；
- `index.md`：先定位，再按需读取；
- `log.md`：记录发生过什么，不重写历史；
- Skill：承接步骤多、会重复使用的工作流。

## 第六步：开始第一次 AI 采访

建好骨架后，让 Codex 一次只问一个问题。建议从这四个问题开始：

1. 你现在最重要的核心目标是什么？
2. 哪些项目正在推进，下一步和阻塞项是什么？
3. 当前最希望沉淀的工作方法或知识主题是什么？
4. 哪些内容已经确认，哪些只是过去的记录或推断？

每次回答后，要求 Codex：

- 更新最相关的页面；
- 保留信息状态；
- 建立必要的 `[[双向链接]]`；
- 更新 `index.md` 的入口摘要；
- 在 `log.md` 追加当天记录；
- 再问一个问题，不一次抛出一长串问卷。

可以复制下面这句继续：

```text
请围绕我的当前核心目标继续采访。一次只问一个问题；
每次回答后先更新相关页面、index.md 和 log.md，再问下一个问题。
```

## 第七步：用 Obsidian 打开 Vault

1. 打开 Obsidian。
2. 选择“打开本地仓库”或“Open folder as vault”。
3. 选择第二步确定的知识库目录。
4. 打开 `README.md` 和 `index.md`，确认链接可以进入生活、工作、学习、目标和项目页面。
5. 随便更新一条测试信息，确认 `log.md` 追加了记录，而不是覆盖历史。

此时 Obsidian 只是一个稳定、舒服的本地阅读界面。知识库能否持续生长，取决于入口、状态、索引和维护规则，而不是插件数量。

## 第八步：验证知识库骨架

### 人工检查

- `README.md`、`AGENTS.md`、`index.md`、`log.md` 都存在；
- `生活.md`、`工作.md`、`学习.md` 和目标页可以从索引进入；
- `素材/待整理/TBD`、`Done`、`待复核` 职责清楚；
- 原始资料没有被覆盖；
- 未确认信息没有写成事实；
- `log.md` 保留历史，只追加新记录。

### 使用本项目脚本检查

下载本项目后，在项目根目录运行：

```bash
python3 skills/local-materials-to-course-kb/scripts/queue_inventory.py \
  --vault-root "/你的/个人知识库路径"

python3 skills/local-materials-to-course-kb/scripts/verify_course_kb.py \
  --vault-root "/你的/个人知识库路径"
```

验证器会报告缺失结构和警告，不会替你修改知识库。

## 第九步：安装 Skill，开始沉淀资料

把本项目中的目录复制到 Codex Skills 目录：

```text
skills/local-materials-to-course-kb
```

重启 Codex，让它重新读取 Skill。然后把新资料放进：

```text
<vault>/素材/待整理/TBD
```

告诉 Codex：

```text
使用 $local-materials-to-course-kb 盘点 TBD，并只处理一个合理批次。
```

Skill 会先查看状态和索引，只读取当前批次需要的页面。完成去重、审核、正式写入、索引和验证后，源资料才会进入 `Done`。

## 第十步：手动跑通后，再考虑自动化

本项目提供三项自动化：

1. 低使用时段资料沉淀；
2. 定期体检本地知识库；
3. 定期创作复盘。

第一次创建时保持 `PAUSED`。确认路径、读取范围、写入白名单和提示词无误后，再手动启用。自动化不是替代结构，而是让已经稳定的结构按节奏运行。

## 为什么知识库变大后仍然可控

- **索引定位**：从 `index.md`、分类索引和主题导航找到目标，不扫全库；
- **主题拆页**：入口只放导航，一个页面解决一个稳定主题；
- **状态文件**：记录阶段、已完成项和下一步，换窗口也能恢复；
- **单批次**：每轮只深读一批，`Done` 只读，剩余 TBD 留待后续。

这四层边界把“知识库有多大”和“本轮需要读多少”拆开。文件可以持续增加，但每次任务只取与当前目标相关的有限集合，因此上下文不会随着知识库增长而线性增加。

## 长期维护只盯四件事

- 入口是否仍然清楚；
- 新资料是否按批次收口；
- 主题页是否重复或过长；
- 待确认、待复核和进行中项目是否长期积压。

先把这个小循环跑起来，再考虑同步、插件和更复杂的自动化。知识库真正有价值的时刻，不是目录看起来很完整，而是下次打开时能直接继续工作。
