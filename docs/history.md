# 优化历史

这个项目不是一次写完的。每次变化，都来自真实使用中暴露出来的问题。

维护约定：凡 `SKILL.md`、`references/` 或 `scripts/` 的对外行为发生变化，必须在同一分支同步核对并更新本页；纯内部重构、测试修复或无行为变化的调整可以不新增条目。

## 1. 从格式转换改成课程编辑

最初只是想把本地文件转成 Markdown。后来发现，真正费时间的是判断哪些值得长期保留、哪些已经过时、哪些能做案例、哪些可以进入 SOP。

于是主流程改成：理解用途 → 盘点 → 提取 → 分类 → 去重 → 审核 → 正式写入。

## 2. 建立八大课程分类

课程知识按工作场景进入一个主分类，其他用途用链接引用，避免一份内容在多个分类里复制。

## 3. 加入审核机制

平台规则、费用、广告功能、账号安全和风险操作都可能变化。项目加入 `99_审核与不沉淀记录.md`，把待核验、过时、证据不足和高风险内容挡在正式知识外。

## 4. 支持 PPT 备注和视频转写包

课程重点经常藏在讲者备注、案例解释和关键帧里。Skill 开始区分可见页面、Speaker Notes、原文转写、导读和用户笔记。

## 5. 从一次吃完改成先盘点、再拆批

文件数量不等于工作量。OCR、图片、英文、本地化、信息密度和分类跨度都会影响质量。于是加入批次评估，每次只处理一个合理批次。

## 6. 建立 TBD 和 Done

早期版本使用课程目录内的 `media/TBD` 和 `media/Done`。它解决了重复处理，但把原始资料和正式知识混在同一层，也让个人知识库入口变得复杂。

## 7. 加入可续跑状态

额度或上下文中断时，不再依赖对话记忆。`当前批次状态.md` 记录阶段、已完成、未完成和下一步，下一次从文件恢复。

## 8. 补上维护脚本

新增：

- `queue_inventory.py`：只读盘点队列和待复核状态；
- `verify_course_kb.py`：检查结构、主题目录、图片链接和积压；
- 标准库自动测试：避免路径迁移后脚本仍悄悄查旧目录。

## 9. 把“大主文档”拆成主题页

长期把正文追加到 `01_知识主文档.md`，文件会越来越重，AI 也会被迫读取大量无关内容。

新结构让入口页只做导航，正文进入 `01_知识主题/`。知识库增长变成增加小页面，单次上下文由任务范围决定。

## 10. 队列移到个人知识库素材层

当前结构统一为：

```text
素材/待整理/
├── TBD/
├── Done/
└── 待复核/
    ├── 课程资料/
    └── 创作复盘/
```

旧 `media/` 和 `98_音视频处理工作区/` 不再是当前路径。课程复核与创作复盘也不再混用一个目录。

## 11. 从课程 Skill 扩展到个人知识库入口

新增 `init_personal_kb.py` 和“从零搭建个人知识库”指南。被分享的人可以先建立自己的 README、AGENTS、index、log、素材队列和主题知识结构，再使用 Skill 做长期沉淀。

## 12. 加入三套内置自动化

现在提供：

1. 资料沉淀队列；
2. 本地知识库每周体检；
3. 每周创作复盘。

三套模板默认都是 `PAUSED`，创建后不会自行运行。资料沉淀负责写入，体检默认只读，创作复盘只看创作材料，职责彼此隔离。

## 13. 重做三项能力与首页建库路径

三项能力不再只是附属模板：Skill 正文明确资料沉淀的上下文边界、体检的七类检查与固定输出，以及创作复盘的证据状态和写入白名单。

公开项目首页也改为“先安装 Obsidian/Codex并建立 Vault，再验证、安装 Skill、最后选择自动化”。这样新用户先拥有可接力的个人知识库，自动化才有稳定的工作对象。

## 14. 把上下文控制从建议升级为硬约束

新增 `kb_health_inventory.py`：在本地统计断链、完全重复、孤岛、待确认、过期和索引覆盖候选，只输出计数与有界路径列表，不输出页面正文。

Skill 同时锁定总索引职责、去重搜索顺序和原始转写读取边界。体检改成“脚本找问题，AI 判断少量候选”的两阶段流程，并用大库回归测试防止以后重新扫描全库正文。

## 15. 加入课程资料对话式复核

课程资料复核升级为一等能力：AI 先总结，用户通过 A/B 交替确认业务结论；知识主题型资料选择一个主分类，跨模块问题场景保留完整场景并引用各模块知识。

新增第四套暂停自动化“课程资料对话式复核”。自动化只恢复当前复核和展示未决 A/B，不替用户确认，不处理 TBD，也不自动归档。

## 16. 把同一判断链限制为两层

真实复核中，A/B 机制如果为了维持问题数量不断派生实施细节，会让已经能写入的结论迟迟无法收口。现在只在确有业务判断时展示最多两个独立问题；同一判断链最多两层，第二层只确认核心结论成立所必需的边界或例外。

第二层确认后必须完成去重、审核和正式写入，其他执行细节标记为“按实际情况判断”。没有必要业务判断时不再为了凑 A/B 出题，已能写入或进入审核记录的内容也不得继续派生同链问题。

## 17. 复核收口后安全归档到 Done

真实使用中发现，`已写入` 若长期停留在待复核目录，会让队列盘点与完成数量失真。因此把
“写入完成”和“物理归档”拆成两个可验证状态：先同步正式知识、审核、索引、状态和日志并
标记 `已写入`；整个资料包无遗留问题且结构检查通过后，在同一轮任务中移动到 `Done`，
移动成功后才标记 `已归档`。

这项规则取代第 15 节中“也不自动归档”的旧默认。部分完成的多资料包不整体移动，
同名目标不覆盖；移动失败保留原位并记录“归档待重试”。移动后同时运行结构验证和
队列盘点，确认没有误动其他复核项。

## 18. 归档一项后自动串行复核下一项

旧规则强调“一次只处理当前项”，容易让自动化在归档一份资料后结束本轮，剩余积压必须
等待用户再次要求。现在把“单项边界”和“队列续跑”拆开：同一时刻仍只保持一个活动项，
不批量深读后续资料；但当前项完成并归档后，只要还有待复核资料，就立即选择下一项并循环，
直到队列清空。

待确认 A/B、上一项纠错、证据缺口、工具或权限失败、额度或上下文切换仍是合法暂停点。
等待用户回答不等于等待用户再次要求继续；回答处理完成后自动恢复当前队列。
