# 这个 skill 是怎么一步步改出来的

这个项目不是一次写完的。它是从真实使用里一点点补出来的。

## 1. 从「文件转换」改成「课程编辑」

一开始的问题很简单：本地资料太多，想转成 Markdown。

但实际用下来发现，转格式不是重点。真正费劲的是：

- 哪些内容值得长期沉淀；
- 哪些只是临时资料；
- 哪些知识已经过时；
- 哪些截图可以变成案例；
- 哪些内容适合写进 SOP；
- 哪些内容不能给新人当操作教程。

所以这个 skill 的核心规则变成了：先理解培训目的，再做提取、审核和沉淀。

## 2. 加入八大分类

为了避免知识库越写越乱，项目把资料分成八类：

- 岗前通用与基础认知；
- Amazon 运营与 Listing 优化；
- 广告推广与站外增长；
- 选品调研与产品开发；
- 项目管理与跨部门协作；
- 制度流程与 SOP 宣讲；
- 管理领导力与导师培养；
- 个人成长与读书技能分享。

一份资料只能有一个主分类。其他用途通过索引交叉引用，不重复复制正文。

## 3. 加入审核机制

培训资料最怕「看起来像经验，其实已经过时」。

Amazon 平台规则、广告功能、费用、账号安全、后台入口、促销资格，这些都可能变化。skill 后来加入了审核记录，把待核验、可能过时、证据不足、高风险内容拦在主知识库外面。

尤其是所谓黑科技，只保留风险识别、防御、自查和合规替代方案，不保留可执行步骤。

## 4. 支持 PPT 备注和视频转写包

很多培训资料的重点不在 PPT 正文，而在讲师备注、讲解话术、案例解释里。

所以后面补了 PPT Speaker Notes Gate，要求把可见页面和演讲者备注分开提取、分开审核。

视频资料也单独整理成 Media Export Package Gate：优先处理带时间戳的原文转写稿，再看导读、关键帧 PPT 和人工笔记。

## 5. 从「一次处理很多文件」改成「先盘点，再拆批」

一开始容易贪多，一次丢十几份资料进去。

后来发现，文件数量不是关键。真正影响质量的是信息密度、图片数量、PPT 备注、OCR、英文资料、分类跨度和是否涉及时效规则。

所以 skill 加了 Batch Sizing Feedback Gate。现在会先反馈资料数量、复杂度、信息密度和建议批次，再决定深度处理哪些资料。

## 6. 加入 TBD 和 Done

手工流程原来是这样：

1. 手动搬几份资料进来；
2. 让 Codex 处理；
3. 处理完删掉；
4. 再搬下一批。

做几轮之后就知道，这个动作本身也很烦。

于是加了 `media/TBD` 和 `media/Done`。

待处理资料都放 `TBD`，处理完的源资料自动移到 `Done`，当前批次文件夹为空就删除。这样资料不会散，也不容易重复处理。

## 7. 加入自动化唤醒

资料多的时候，还有一个现实问题：额度会用完。

以前的做法很原始，甚至有点好笑：半夜醒来看看额度恢复没恢复，恢复了就继续跑一批。勤奋是勤奋，但人不该这么用。

后面就把规则改成了自动化友好的模式：

- 每次自动化只处理一个批次；
- 没处理完就写状态；
- 下一轮从状态文件恢复；
- `TBD` 还有资料就继续排队；
- `Done` 永远不自动重读。

这个设计牺牲了一点速度，但换来稳定、可恢复和可检查。

## 8. 初始化脚本补齐目录

最后一个坑是：文档写了 `TBD` 和 `Done`，但换电脑时目录不一定真的存在。

所以初始化脚本也改了。现在第一次运行会自动创建知识库根目录、八大分类、任务状态文件、`media/TBD` 和 `media/Done`。

这样别人拿到这个项目，不需要先研究目录结构，可以直接初始化。
