# 测试与回归样例

每次修改这个 skill，建议至少跑一遍自动脚本测试，再用几个典型资料场景做人工回归。

## 自动测试

项目内置了标准库测试，不需要安装第三方依赖：

```bash
python3 -m unittest tests/test_maintenance_scripts.py
```

目前覆盖：

| 场景 | 验证什么 |
|---|---|
| 队列盘点 | `TBD`、`Done`、隐藏文件、`98_音视频处理工作区` 状态统计是否正确 |
| 缺目录检查 | 缺少 `media/Done` 时，结构验证脚本是否报错 |
| 初始化结构检查 | 初始化后的知识库是否通过验证，并对 `.DS_Store`、`待复核` 给出警告 |

## 人工回归样例

建议保留 5 类小样例。每次大改 Skill 时，挑 1-2 个跑一下。

| 样例 | 应该验证的行为 |
|---|---|
| 单个 Word/PDF 文字资料 | 能先判断课程目的，再提炼知识卡片，不直接全文改写 |
| 多个同主题 Word 文档 | 能先盘点、分批、去重，而不是一口气深读所有文件 |
| PPT/PPTX 带演讲者备注 | 能区分可见页面和备注，备注缺失时标记 `备注待人工确认` |
| 视频转写包 | 能优先处理带时间戳原文，检查关键帧和导读，不把所有文件当散件 |
| Amazon 高风险/时效资料 | 能把政策、费用、账号安全、黑科技内容放进审核或待核验，而不是写成操作教程 |

## 通过标准

- 原始资料没有被覆盖；
- 只选择一个合理批次；
- 有明确主分类；
- 已审核内容和不沉淀内容分开；
- 索引、案例表、审核记录能对应上；
- 如果中断，`当前批次状态.md` 能让下一轮继续。
