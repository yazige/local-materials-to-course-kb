# Codex 自动化设置

这个 skill 可以单次运行，也可以配合 Codex 自动化定时跑。

单次运行适合少量资料。资料很多时，更推荐自动化：把资料放进 `media/TBD`，让 Codex 每隔一段时间醒来处理一批。

## 推荐设置

建议先用保守方案：

- 每 2 小时检查一次；
- 每次最多处理一个批次；
- 处理完一个批次就停止；
- 剩余资料留在 `TBD`，下一轮继续；
- 如果额度、上下文或资料复杂度卡住，就写状态文件，下一轮恢复。

这样不会把一次运行拉得很长，也不容易因为上下文变重而浪费 token。

## 自动化任务提示词

在 Codex 自动化里创建一个定时任务，任务内容可以复制下面这段：

```text
使用 local-materials-to-course-kb skill 的规则处理本地课程知识库资料队列。

知识库根目录为：
~/Desktop/AI工作台/06_培训教程与分享资料/本地资料转课程知识库

每次运行先检查 00_任务状态/当前批次状态.md 是否有未完成批次；如有，优先恢复该批次。

如果存在 98_音视频处理工作区，则先盘点其中的 处理中、测试中、待复核、已写入、已归档 状态。若待复核积压较多，先报告数量，并优先选择 1-3 个相关待复核工作区收口；不要把待复核草稿当成新的 TBD 来源重复处理。

如果没有未完成批次，则检查 media/TBD。

如果 media/TBD 为空，记录队列为空并停止，不处理 media/Done。

如果 media/TBD 有文件或文件夹，先做资料盘点，反馈资料数量、文件类型、复杂度、信息密度、分类跨度和建议批次；然后只选择一个合理批次进行课程知识沉淀。

处理时遵守知识审核、去重、分类、图片筛选、PPT 备注提取、英文本地化、Amazon 时效规则核验和安全处理要求。

完成一个批次后，将已处理源资料移动到 media/Done/YYYY-MM-DD_批次名/，删除空的当前批次文件夹，更新 00_总索引.md、分类索引、案例表和 00_任务状态 文件。

每次运行最多处理一个批次，剩余 TBD 资料留给下一次自动化。

若遇到额度、上下文、文件复杂度、OCR、图片、官方核验或其他中断，保留当前批次资料，更新当前批次状态和下一步动作，然后停止等待下一次自动化继续。

如果本轮改动了目录、索引、图片或源资料位置，结束前运行 verify_course_kb.py 做结构检查，并把错误或警告写进最终反馈。

不要删除原始资料，不要处理 media/Done，除非用户明确要求。
```

## 为什么不建议一轮跑完

课程知识沉淀不是机械搬运。一个批次里可能有截图、PPT 备注、视频转写、过时规则、隐私信息、重复知识和风险内容。

如果一轮跑太多，表面上省事，实际容易出三个问题：

1. 上下文越来越长，后面判断变慢；
2. token 消耗变高，额度很快见底；
3. 最后的课程化质量变差，容易变成大段总结。

所以这个项目默认选择「慢一点，但稳一点」。

## 关于额度恢复

Codex 不一定能稳定读取你的额度恢复时间。更稳的办法是让自动化定时醒来试一次。

如果额度还没恢复，本轮会停止；等额度恢复后，下一轮自动化继续。

这比半夜醒来摸一下电脑强。人要睡觉，资料可以排队。
