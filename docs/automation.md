# 四套 Codex 自动化

本项目内置四套自动化模板。完整提示词在：

```text
skills/local-materials-to-course-kb/references/automation-presets.md
```

## 安全默认值

- 新建或更新后保持 `PAUSED`；
- 只保存配置，不立即运行；
- 用户检查路径和提示词后，再手动启用；
- 每个自动化只负责一种工作。

## 1. 资料沉淀队列

作用：检查 `素材/待整理/TBD`，恢复未完成批次，或选择一个新批次沉淀。

边界：

- 每次最多处理一个批次；
- `Done` 只读；
- 完成审核、索引和验证后才归档；
- 中断时写状态，不把半成品移入 Done。

TBD 较多时安排在低使用时段，避开 Codex 高频使用时间。每次仍只处理一个批次，
不得一轮清空或持续扩大上下文。

## 2. 课程资料对话式复核

作用：恢复当前课程资料复核，把 AI 已总结但仍需业务判断的结论以 A/B 两题交给用户确认。

边界：

- 有进行中复核时先恢复，不另选资料；
- 已有 A/B 时只展示原题，不先修改知识库；
- A/B 只承载独立核心判断；同一判断链最多两层（核心结论 → 必要边界/例外），第二层后收口，实施细节按实际情况判断；
- 仅当当前项仍有阻塞写入的独立核心结论时才补新 A/B，不为维持问题数量继续同链追问；
- 未确认不写入，自动化不能替用户判断；
- 不处理 TBD，不运行体检或创作复盘；
- 不自动删除、归档或扩大到其他待复核项。

建议安排在用户愿意参与判断的时段，例如每天一次或每周数次。

## 3. 本地知识库每周体检

作用：检查断链、重复、孤岛、未整理、待确认、过期、索引覆盖和队列积压。

边界：

- 默认只读；
- 先给问题清单；
- 不自动批量修复；
- 不触发资料沉淀。

固定输出健康分、问题、最优先的 3 件事和下一步。

建议每周一次。

## 4. 每周创作复盘

作用：对照 AI 初稿、人工修改意见和最终稿，提炼可复用的创作规律。

边界：

- 只读 `待复核/创作复盘`；
- 材料不全时不猜测；
- 对照 AI 初稿、修改意见和最终稿；
- 区分稳定规律、待观察和待确认；
- 单次复盘进入 `reviews/`，重复出现的稳定规律才进入 `wiki/`；
- 只允许写入 `reviews/`、指定 `wiki/`、`index.md` 和 `log.md`；
- 不读取课程资料复核区。

建议每周一次，或安排在固定创作日之后。

## 为什么默认暂停

自动化会长期运行。第一次设置时，路径写错、边界不清或目录尚未准备好，都可能造成重复处理。先保存为暂停状态，让人检查一次，比“创建后立刻跑一遍看看”更稳。

需要测试时，也应由用户明确选择一个小样例手动触发。
