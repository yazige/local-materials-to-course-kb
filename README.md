# Local Materials To Course KB

一套给 Codex 使用的本地知识库工作流：先搭好能长期接力的个人知识库，再把 PDF、Word、PPT、图片、英文资料和音视频转写包，沉淀成主题知识、案例、SOP、课程素材与审核记录。

它不是“文档转 Markdown”工具。真正要解决的是：资料越攒越多，收藏夹越来越满，课程、会议转写、学习笔记一层套一层，最后真正能拿来培训新人、写 SOP、做项目复盘的内容却没有沉淀下来。

如果你也经常这样：

- 看到好资料先存起来，想着以后整理；
- 做培训时发现素材很多，但能直接讲的案例很少；
- 想把经验变成 SOP，却总卡在分类、去重、审核和重写；
- 视频转写了一批 Word、PPT，最后不知道应该放在哪里；
- 换个 AI 或新开一次对话，就得重新解释知识库结构；
- 半夜还惦记着额度恢复后再跑一批——人不该守着队列，资料应该自己排队。

这个项目提供的不是一次性摘要，而是一套可持续维护、可追溯、可跨工具接手的知识系统。

## 适合谁

- 培训负责人、讲师、内训师；
- 做 SOP、流程、项目复盘和方法沉淀的人；
- 囤了很多 PDF、Word、PPT、视频转写稿的人；
- 做 Amazon 运营、电商培训、选品调研、广告推广的人；
- 想做个人知识库，但不想每天手工搬文件、补索引的人。

## 首页主路径：先建库，再用 Skill

顺序很重要。没有稳定入口、状态和索引，自动化只会更快地制造混乱。

1. **安装 Obsidian**：它负责打开本地 Markdown、浏览链接、搜索和人工阅读。
2. **安装 Codex**：它负责采访、整理、更新与验证文件。
3. **选择 Vault**：选一个长期稳定的本地目录；开始前先确认存放路径与现阶段核心目标。
4. **让 AI 采访**：先把已有对话整理成个人信息摘要，再让 AI 一次只问一个问题；每次回答后立即更新相关页面。
5. **建立三层结构**：素材层保留原文，笔记层沉淀结论，规则层规定 AI 怎样接手。
6. **建立入口页**：至少包含 `生活.md`、`工作.md`、`学习.md`、`index.md`、`log.md`、`AGENTS.md` 和一个核心目标页。
7. **持续更新**：冲突显式保留，未知不编造；同步更新交叉链接、索引与日志。
8. **用 Obsidian 打开**这个目录作为 Vault，人工检查导航和链接。
9. **运行验证**，确认目录、主题入口和队列可用。
10. **安装 Skill**，再使用资料沉淀、课程资料对话式复核、知识库体检和创作复盘。
11. **可选配置四项自动化**；创建后默认 `PAUSED`，检查无误再启用。

完整操作见[从零搭建个人知识库](docs/build-your-personal-kb.md)，安装 Skill 见[安装与初始化](docs/install.md)。

Obsidian 是本地 Markdown 的阅读、链接和检索界面。真正让知识库长期可用的，是目录职责、索引、状态文件、主题拆页和 Skill 的处理规则。

## 为什么不会越用越容易爆上下文

- **索引定位**：先读 `index.md` 和分类索引，再打开当前任务相关页面；
- **主题拆页**：`01_知识主文档.md` 只做导航，正文进入 `01_知识主题/`；
- **状态文件**：`当前批次状态.md` 记录阶段、已完成项和下一步，换对话也能续跑；
- **单批次**：每次只处理一个合理批次，`Done` 只读，剩余 TBD 留给下一轮。

知识库增长时增加的是可定位的小页面，而不是每轮都要读取的总文档。单次上下文由当前任务决定，不会随着知识库体量线性膨胀。

### 防止流程走样

- `00_总索引.md` 只放导航、数量、最近更新和一句摘要；
- 去重先查总索引和分类索引，再做文件名、标题和关键词搜索，只打开候选主题页；
- 盘点与体检不读取原始转写，只有当前批次进入提取或审核后才读取；
- 体检由脚本先找问题，AI 只判断少量候选，不把全库正文送进模型。

## Skill 的四项一等能力

### 1. 资料沉淀队列

先看状态，再盘点队列，然后选择一个合理批次。它会：

1. 判断资料要服务什么主题、岗位或业务场景；
2. 评估数量、格式、信息密度和分类跨度；
3. 提炼知识点、案例、图片、SOP、话术和模板；
4. 把过时、证据不足、高风险或隐私敏感内容挡在正式知识外；
5. 完成去重、审核、写入、索引和验证后，才把源资料归档到 `Done`。

TBD 太多时只拆批，不一轮清空；需要续跑时，建议放到 Codex 低使用时段。目标是形成可复用的课程资产，而不是追求一次吃完。

建议批次：

| 资料情况 | 一次深度处理 |
|---|---:|
| 同主题、文字型 Word/PDF | 6–10 个 |
| 混合主题或分类不明 | 3–5 个 |
| 图片、备注较多的 PPT | 2–4 个 |
| 音视频转写资料包 | 1–3 包 |
| 规则、费用、风控、时效性内容 | 2–4 个 |
| 质量优先的课程沉淀 | 4–6 个 |

### 2. 课程资料对话式复核

用于收口 `素材/待整理/待复核/课程资料` 中的已有草稿。AI 先总结，只把需要业务判断的结论交给用户确认：

- A/B 只承载独立核心判断，每题写清模块、场景、判断对象和排除范围；
- 同一判断链最多两层：核心结论 → 必要边界/例外；第二层后收口，实施细节按实际情况判断，不为维持 A/B 数量继续追问；
- 知识主题型资料选择一个主分类；跨模块问题场景保留完整场景，知识回到对应模块并建立双向链接；
- 未确认不写入，确认后同步正式页、审核记录、复核草稿、索引、状态、接力摘要和日志。
- 资料包内所有独立资料都收口且同步、验证通过后，在同一轮任务中移动到 `Done`；部分完成不整体移动，同名归档不覆盖，移动失败则保留 `已写入` 并记录“归档待重试”。

对应自动化只负责恢复现场和展示 A/B，不会替用户确认；只有用户确认后已经满足完整归档门槛时，才执行上述安全移动。

### 3. 定期体检本地知识库

默认只读。检查断链、重复、孤岛、未整理、待确认、过期和索引覆盖，输出：

- 健康分；
- 本次发现的问题；
- 最优先处理的 3 件事；
- 建议下一步。

先运行：

```bash
python3 skills/local-materials-to-course-kb/scripts/kb_health_inventory.py \
  --vault-root "/你的/个人知识库路径"
```

脚本只输出计数、问题类型和有界候选路径，不输出页面正文。AI 再从每类候选中打开最优先的 1–3 页判断。

### 4. 定期创作复盘

只读取指定创作资料目录，对照 AI 初稿、修改意见和最终稿；区分稳定规律、待观察、待确认，并把写入限制在 `reviews/`、指定 `wiki/`、`index.md` 和 `log.md`。

## 视频、直播和会议资料怎么进入

视频课、直播回放和会议录音可以先用任意可靠的转写服务处理，例如[通义听悟](https://tingwu.aliyun.com/home)。建议：

- 长视频按主题拆成 1–3 个资料包；
- 优先保留带时间戳的原文转写；
- 导读、关键帧 PPT、讲者备注和自己的学习笔记放进同一资料包；
- 不同主题不要为了省事塞进一个转写文件；
- 平台规则、时长和费用以服务商当前页面为准。

Skill 会把它们作为一个有上下文的资料包处理，而不是把 Word、PPT 和图片当成互不相关的文件。详细流程见[视频资料转课程知识库](docs/video-to-course-kb.md)。

## 快速安装与验证

把 `skills/local-materials-to-course-kb` 复制到 Codex Skills 目录，重启 Codex，然后运行：

```bash
python3 skills/local-materials-to-course-kb/scripts/init_personal_kb.py \
  --vault-root "/你的/个人知识库路径"

python3 skills/local-materials-to-course-kb/scripts/verify_course_kb.py \
  --vault-root "/你的/个人知识库路径"
```

把资料放入 `<vault>/素材/待整理/TBD`，再告诉 Codex：

```text
使用 $local-materials-to-course-kb 盘点 TBD，并只处理一个合理批次。
```
