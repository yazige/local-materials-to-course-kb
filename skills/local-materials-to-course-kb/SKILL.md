# Local Materials To Course KB

## 核心原则

这不是文件转换器，而是一套可续跑的知识沉淀工作流。

- 原始资料可追溯，不覆盖。
- 正式知识先审核、去重，再写入。
- 资料沉淀一次只处理一个合理批次；课程资料复核一次只保持一个活动项，收口后自动串行下一项。
- `Done` 只读，不自动重新处理。
- `01_知识主文档.md` 只做导航；正文按主题拆到 `01_知识主题/`。
- `00_总索引.md` 只允许保存导航、累计数量、最近更新和一句摘要，不写知识正文。
- 状态、索引和文件承接上下文，不依赖一段越来越长的对话。

## 不可绕过的上下文边界

1. 去重顺序不可跳过：`00_总索引.md` → 分类 `00_索引.md` → 文件名、标题和关键词搜索 → 候选主题页。没有候选时停止，不得把整个分类正文读入上下文。
2. 盘点和体检禁止读取原始转写稿。只有当前批次进入提取或审核阶段后，才允许读取该批次的原始转写稿；已有完整草稿时优先审稿，不回读原始媒体。
3. 体检先运行 `scripts/kb_health_inventory.py`，先看统计和候选路径，再定向打开每类最优先的 1–3 个页面。
4. 禁止把全库正文或脚本读取到的正文批量送入模型。脚本可以在本地解析文件，但输出只保留计数、问题类型和有界路径列表。

## 标准目录

把用户指定的 Obsidian 或 Markdown 目录视为 `<vault>`：

```text
<vault>/
├── README.md
├── AGENTS.md
├── index.md
├── log.md
├── 素材/待整理/
│   ├── TBD/
│   ├── Done/
│   └── 待复核/
│       ├── 课程资料/
│       └── 创作复盘/
├── 知识库/课程知识库/
│   ├── 00_任务状态/
│   ├── 00_总索引.md
│   ├── 99_审核与不沉淀记录.md
│   └── <分类>/
│       ├── 00_索引.md
│       ├── 01_知识主文档.md
│       ├── 01_知识主题/

│       ├── 03_可复用话术&模板.md

```

用户另有项目级规则时，以项目规则和真实目录为准，不要硬改成模板名称。

## 开始前：只读入口

优先读取：

1. `<vault>/README.md`
2. `<vault>/AGENTS.md`
3. `<vault>/index.md`
4. `<vault>/知识库/课程知识库/00_任务状态/当前批次状态.md`
5. 当前任务直接相关的分类索引和主题页

不要因为“可能有用”就扫描整个知识库。只有用户明确要求体检或任务确实需要时，才扩大范围。

## 初始化

### 新建完整个人知识库

运行相对本 Skill 的脚本：

```bash
python3 scripts/init_personal_kb.py --vault-root "<vault>"
```

脚本只创建缺失的文件和目录，不覆盖已有知识。

### 只补齐课程知识库

```bash
python3 scripts/init_course_kb.py --vault-root "<vault>"
```

初始化后先运行结构验证，再让用户投放资料：

```bash
python3 scripts/verify_course_kb.py --vault-root "<vault>"
```

## 选择工作模式

根据请求只进入一个主模式：

| 模式 | 入口 | 默认行为 |
|---|---|---|
| 资料沉淀 | `素材/待整理/TBD` | 一次一个批次，完成后归档到 Done |
| 课程资料复核 | `素材/待整理/待复核/课程资料` | 收口已有草稿，不当作新资料重复提取 |
| 知识库体检 | 入口文件和相关索引 | 默认只读，先列问题，不自动修复 |
| 创作复盘 | `素材/待整理/待复核/创作复盘` | 对照初稿、修改意见、终稿提炼规律 |
| 自动化设置 | `references/automation-presets.md` | 只创建/更新配置，默认暂停，不运行 |

不要在同一次运行里把多个模式混成一次全库重构。

## 能力一：资料沉淀队列

本能力用五个边界控制上下文：**状态优先、索引定位、主题拆页、一次一个批次、Done 只读**。
先用状态文件恢复现场，再用索引找到目标主题，只打开当前批次需要的页面；不得一轮清空 TBD。

当 TBD 明显超过一个合理批次时：

1. 只盘点队列并给出拆批建议；
2. 本轮最多完成第一批，其余留在 TBD；
3. 主动建议用户配置“资料沉淀队列”续跑自动化；
4. 请用户选择低使用时段，避开用户高频使用 Codex 的时间；
5. 自动化每次仍只处理一个批次，不得连续扩张读取范围。

### 1. 恢复优先

开始时先检查 `当前批次状态.md`：

- 有未完成批次：先恢复，不选择新资料。
- 新资料同时到达：登记到 `待处理资料队列.md`，不要混入旧批次。
- 准备暂停：写清已完成、未完成、当前阶段和下一步。

状态阶段使用：

```text
盘点 → 提取 → 知识卡片 → 去重 → 审核 → 待写入 → 索引更新 → 验证
```

### 2. 先盘点，再深读

大型队列先运行：

```bash
python3 scripts/queue_inventory.py --vault-root "<vault>"
```

盘点只读文件名、类型、目录和必要元数据，不打开原始转写正文。对文件夹、3 个以上文件、混合格式或分类不明的资料，先反馈：

- 文件数量和类型；
- 复杂度与原因；
- 信息密度；
- 可能涉及的分类；
- 建议处理方式；
- 建议批次规模和第一批选择。

建议批次：

| 资料情况 | 一次深度处理 |
|---|---:|
| 同主题、文字型 Word/PDF | 6–10 个 |
| 混合主题或分类不明 | 3–5 个 |
| 图片/备注较多的 PPT | 2–4 个 |
| 音视频导出资料包 | 1–3 包 |
| 规则、费用、风控、时效性内容 | 2–4 个 |
| 质量优先的课程沉淀 | 4–6 个 |

超过建议规模时，先做拆批计划，只处理第一批。

### 3. 建立当前批次

从 `TBD` 选择一个主题一致的批次，移动到：

```text
素材/待整理/当前批次_YYYY-MM-DD_主题_v1_处理中/
```

立即在 `当前批次状态.md` 记录批次 ID、源文件、阶段和下一步：

- 知识主题型记录主分类；
- 问题场景型记录 `资料类型：问题场景型`、场景入口和涉及模块，不伪造单一主分类。

移动冲突时建立日期/批次子目录或稳定后缀，绝不覆盖。

### 4. 提取为知识卡片

先读适用参考：

- 音视频导出包、PPT、讲者备注：`references/media-package-and-ppt.md`
- 英文或中英混合资料：`references/english-source-localization.md`
- 分类与审核：`references/classification-and-audit.md`

每个可复用知识点形成紧凑卡片：

```markdown
### 知识卡片

- source_file:
- source_type:
- inferred_topic:
- suggested_primary_category:
- core_point:
- course_ready_summary:
- usage_scenario:
- approved_candidate:
- case_or_image_candidate:
- reusable_template_candidate:
- audit_risk:
- duplicate_or_conflict:
- uncertain_item:
- source_trace:
```

不交付大段原文复述。多文件并行提取时，各处理单元必须使用互不重叠的文件集；最终分类、去重、审核和正式写入仍由主任务统一完成。

### 5. 分类、去重和审核

先判断资料类型，再决定分类方式：

- **知识主题型**：每份资料只选择一个主分类，其他用途只做交叉引用。
- **问题场景型**：不强行归入单一分类；保留完整场景，把可复用知识分别维护到对应模块，场景页通过双向链接引用模块知识，不复制多份正文。

写入前：

1. 严格按“总索引 → 分类索引 → 文件名、标题和关键词搜索 → 候选主题页”定位；
2. 重复内容合并或交叉链接，不新建同义页面；
3. 优先保留长期稳定的原则、框架和判断方法；
4. 过时、错误、证据不足、隐私敏感、违规或高风险内容写入 `99_审核与不沉淀记录.md`；
5. 时间敏感规则、费用、平台入口和风险操作不得直接写成当前 SOP。

### 6. 正式写入

正文写入：

```text
<分类>/01_知识主题/<稳定主题名>.md
```

一个页面解决一个稳定主题。主题页至少包含：

- 主题结论；
- 适用场景；
- 方法或步骤；
- 边界与风险；
- 来源追溯；
- 相关主题链接。

`01_知识主文档.md` 只增加或更新主题导航，不继续堆长正文。

其他内容分流：

- 真实案例、截图、图表：`02_案例库.md` 和 `images/`
- SOP、检查清单、课程话术：`03_可复用话术&模板.md`
- 不沉淀项：`99_审核与不沉淀记录.md`

随后更新分类 `00_索引.md`、`00_总索引.md` 和相关案例表。

### 7. 归档和收口

只有在正式写入、审核记录、索引和验证全部完成后，才把本批源资料移动到：

```text
素材/待整理/Done/YYYY-MM-DD_批次名/
```

移动成功且当前批次目录为空时，删除空目录。处理失败或中断时，保留当前批次，不得移入 Done。

每次运行最多完成一个批次，剩余 TBD 留给下一次。

## 能力二：课程资料对话式复核

读取 `references/workspace-lifecycle.md`。本能力用于收口已有草稿，不把待复核区当作新资料队列。

### 恢复与选取

- 有进行中的对话式复核时先恢复，不选择新资料；已有未决 A/B 时只展示原问题，不先修改知识库。
- 没有进行中事项时，先按状态盘点，只选择下一项作为唯一活动复核项；不要预读后续资料。
- 优先从资料摘要、分类判断、审核与不沉淀记录、可沉淀知识和复核清单开始。草稿完整时不回读原始音视频；确有证据缺口时才定向读取当前项原文。

### 判断与提问

1. AI 先总结材料，只把需要用户业务判断的结论提交确认，不要求用户逐份阅读资料。
2. 先判断知识主题型或问题场景型，再按本 Skill 的分类规则处理。
3. 需要用户判断时，最多同时展示 A、B 两个独立的核心结论；没有必要业务判断时，不得为了凑 A/B 而出题。每题写清所属模块、适用场景、本题判断对象、不包含的范围和 AI 建议。
4. 同一判断链最多两层：第 1 层确认核心结论；第 2 层只补充该结论成立所必需的边界或例外。第 2 层确认后必须收口，实施细节标记为“按实际情况判断”，不得为了维持 A/B 数量继续生成同链追问。
5. 用户回答 A 时，只处理 A，原样保留仍属独立判断的 B；只有当前项仍有阻塞写入的独立核心结论时，才补入新的 A。用户回答 B 时反向执行。
6. 用户指出上一项不正确时，暂停新问题，先修正并验证，再恢复 A/B 交替。
7. 未收到明确确认时，不把建议写成已确认知识。

### 确认后的同步

只同步与本次确认直接相关的内容：

- 正式主题页、必要模板及审核与不沉淀记录；
- 当前复核项的资料摘要、可沉淀知识和复核清单；
- 实际受影响的分类索引、总索引或场景索引；
- 当前批次状态、接力摘要、`index.md` 和 `log.md`。

写入前仍要去重、审核和核对来源。两层内形成结论后，若当前项的其余内容已能写入或已进入审核与不沉淀记录，应立即同步并标记该项“已写入”，不得继续派生同链问题。`已写入` 是归档前的短期状态，不等于已进入 `Done`。

### 复核完成后的自动归档

这里的“自动”是指：同一轮课程资料复核任务完成收口时，由执行该任务的 AI 继续完成移动；不是无人运行任务时的后台自动化。

满足以下门槛后，必须在同一轮任务内把复核资料包移入 `素材/待整理/Done/`：

1. 当前资料包内所有独立资料均已完成复核；必要结论已确认或进入审核与不沉淀记录，没有遗留 A/B 或其他后续动作。
2. 正式主题页、必要模板、审核记录、当前项复核文件、相关索引、当前批次状态、接力摘要、`index.md` 和 `log.md` 已同步。
3. 结构、链接、索引和必要文件检查已通过。

归档时：

- 将 `素材/待整理/待复核/课程资料/<资料包>` 移动到 `素材/待整理/Done/<稳定批次名>_已归档`，并同步所有仍有效的路径引用。
- 只有移动成功后才能标记 `已归档`。移动是归档，不是删除；不得丢弃包内原文、草稿、审核记录或过程文件。
- 一个资料包包含多份资料时，只要任一资料仍在复核，就不得整体移动。能在不破坏来源追溯和内部引用的前提下安全拆包时才拆分，否则保留原包并记录剩余项。
- `Done` 已有同名目标时，使用日期、批次子目录或稳定后缀消除冲突，绝不覆盖、合并或删除既有归档。
- 移动失败时，资料包保留原位并维持 `已写入`，在当前状态、接力摘要和 `log.md` 记录“归档待重试”、失败原因和下一步；不得声称已归档。
- 移动后运行 `verify_course_kb.py` 和 `queue_inventory.py`，最终说明源路径已清空、目标路径存在、当前复核项和剩余积压未被误动。

### 收口后的连续复核

当前项完成并归档后，不要因为“一次只处理一个复核项”而结束整个课程资料复核任务：

1. 运行队列盘点；如果仍有待复核资料，立即选择下一项，并把它登记为唯一活动复核项。
2. 一次只保持一个活动复核项，不批量深读后续资料；“连续”是逐项串行，不是扩大单项上下文。
3. 对下一项重复“摘要 → 分类 → 去重 → 审核 → 必要确认 → 写入 → 验证 → 归档”，完成后循环继续，直到队列清空。
4. 下一项出现待确认 A/B 时，展示现有问题并等待用户回答；等待回答不等于等待用户再次要求继续，回答处理完后自动恢复循环。
5. 只有待确认 A/B、用户指出上一项错误、资料或证据缺口、工具/权限失败、额度或上下文切换等真实阻塞可以暂停。暂停前必须同步当前状态、接力摘要和 `log.md`，不得跳过受阻项去处理后续资料。

## 能力三：定期体检本地知识库

默认只读：

1. 先运行 `python3 scripts/kb_health_inventory.py --vault-root "<vault>" --format json`；
2. 只读取报告中的统计、问题类型和候选路径，不读取脚本扫描到的正文；
3. 每类最多选择 1–3 个高优先级候选页做语义判断；
4. 检查断链，区分真实链接与 OCR、代码或转写噪声；
5. 检查完全重复文件；近义主题只对索引搜索得到的候选页做比较；
6. 检查没有任何入口指向的孤岛候选；
7. 检查 TBD、待复核、未完成批次等未整理积压；
8. 检查“待确认”“冲突待确认”等标记；
9. 检查可能过期的规则、入口、费用、状态和进行中项目；
10. 检查总索引、分类索引和主题导航的索引覆盖；
11. 检查旧 `media/` 和 `98_音视频处理工作区/` 路径残留。

`kb_health_inventory.py` 在本地读取必要的 Markdown 以计算链接和哈希，但不会输出正文；候选列表默认每类最多 50 项并标记是否截断。不得绕过候选列表改成全库正文审阅。

报告固定输出：

- 健康分：0–100，并说明主要扣分项；
- 本次发现的问题，按严重程度排序；
- 最优先的 3 件事；
- 建议下一步。

最后明确写出“本次为只读体检，未修改知识库”。没有用户授权，不修复、不移动、不删除文件。

## 能力四：定期创作复盘

创作资料严格限定在 `<vault>/素材/待整理/待复核/创作复盘/`。不得去课程资料区或全库寻找创作素材。

1. 按作品对齐 AI 初稿、人工修改意见和最终稿；
2. 提炼标题、开头、节奏、结构、表达禁忌和修改规律；
3. 用户多次明确强调，或至少两个独立作品重复出现，才标记为**稳定规律**；
4. 单个作品且证据不足的规律标记为**待观察**；
5. 新证据与旧规律冲突时标记为**待确认**，保留双方证据；
6. 每条判断记录作品、文件路径或复盘链接，确保来源可追溯；
7. 材料不完整时只列证据缺口，不猜测修改动机。

允许写入仅限：

- `reviews/YYYY-MM-DD-创作复盘.md`
- `wiki/写作风格.md`
- `wiki/脚本结构.md`
- `wiki/标题方法.md`
- `wiki/AI协作规则.md`
- `index.md`
- `log.md`

单次证据先写入 `reviews/`；只有达到稳定规律标准才更新 `wiki/`。不得静默覆盖旧规律，不得移动或修改原始创作材料。

## 四种自动化

用户要求设置自动化时，完整读取 `references/automation-presets.md`。

内置模板：

1. 资料沉淀队列；
2. 课程资料对话式复核；
3. 本地知识库每周体检；
4. 每周创作复盘。

除非用户明确要求启用或立即执行：

- 新建和更新后保持 `PAUSED`；
- 不自动运行；
- 不把体检改成自动修复；
- 不让对话式复核替用户确认、生成第三个并行问题或绕过进行中事项；
- 不让创作复盘读取课程资料区；
- 不让资料沉淀一次清空整个 TBD。

## 完成前验证

读取 `references/completion-checklist.md`，并在结构、链接、索引、图片或源文件位置有变化时运行：

```bash
python3 scripts/verify_course_kb.py --vault-root "<vault>"
```

该验证会在检查前自动删除知识库根目录内的 `.DS_Store`（macOS Finder 元数据），并在结果中说明清理数量；只处理这一种文件，不删除其他隐藏文件、目录、素材或归档。

体检模式同时运行：

```bash
python3 scripts/kb_health_inventory.py --vault-root "<vault>"
```

最终说明：

- 完成了哪个模式和批次；
- 修改了哪些正式页面、索引和状态；
- 源资料是否已进入 Done；
- 验证结果与警告；
- 未完成项、风险和下一步。
